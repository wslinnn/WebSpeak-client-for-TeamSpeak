## О проекте

| Логика | Описание |
| --- | --- |
| **WHAT** | WebSpeak — самостоятельно размещаемый веб-клиент и голосовой шлюз для TeamSpeak 3 и TeamSpeak 6. |
| **WHY** | Пользователям не нужно устанавливать настольный клиент: достаточно открыть браузер, а оператор сохраняет контроль над сервером и данными. |
| **HOW** | После запуска настройте цель TeamSpeak и политику доступа в панели администратора. Браузер отвечает за интерфейс и аудио, WebSpeak — за шлюз. |

## Онлайн-демо

## 🧩 Расширенные функции

### WebRTC

Включается в **Панель администратора → Сервер → Расширенные настройки**. До включения задайте диапазон UDP-портов (по умолчанию `40000–40099`), откройте его в firewall и сохраните. При включённом WebRTC диапазон заблокирован; новые подключения используют WebRTC, а неподдерживаемые браузеры переходят на совместимый транспорт. Для публичного доступа нужен HTTPS.

### Голосовой WebRTC за обратным прокси или TCP-туннелем

В расширенных настройках WebRTC в панели администратора доступны:

- **Публичный адрес медиа**: IP или домен, по которому шлюз WebSpeak доступен по UDP; без протокола, пути и порта. Он имеет приоритет над адресом, определённым по веб-входу; если поле пустое, адрес определяется по `Origin`, `X-Forwarded-Host` или `Host`. Домены преобразуются в IP-кандидаты. Домен прокси не обязательно является медиа-адресом.
- **Включение IPv6-кандидатов**: по умолчанию отключено; при включении кандидаты IPv4 сохраняются и дополнительно собираются кандидаты IPv6. Для этого нужны работающий маршрут IPv6 и открытый UDP-диапазон в firewall.
- **Голосовой STUN-сервер**: например `stun:turn.teamspeak.com:3478`; браузер и шлюз используют один и тот же сервис, чтобы обнаружить своё публичное отображение. Пустое поле сохраняет прежнее поведение: шлюз werift использует встроенный в библиотеку STUN, браузер STUN не настраивает. Сейчас поддерживаются только доступные по IPv4 UDP-STUN-домены или IPv4-адреса; IPv6-литералы, TURN и учётные данные не принимаются. IPv6-медиа-кандидаты не зависят от переключателя STUN.

После сохранения переподключитесь. Доступность страницы и WebSocket через обратный прокси не означает, что медиа-UDP доступен; STUN только находит адреса, не передаёт звук и не гарантирует обход любого NAT. При наличии только TCP-туннеля без рабочего UDP/IPv6-пути используется совместимый транспорт. Следует открыть весь настроенный диапазон UDP-портов; при статической проброске портов сохраняйте то же соответствие портов.

### ICE для демонстрации экрана

Медиа демонстрации экрана по-прежнему предпочитает прямое соединение между браузерами; WebSpeak только передаёт сигнальные сообщения. По умолчанию используются публичные STUN-серверы TeamSpeak для поиска внешних кандидатов, STUN не передаёт медиаданные. Авторизованный внешний TURN можно задать через `WEBSPEAK_SCREEN_SHARE_ICE_SERVERS` в виде JSON-массива, например:

```json
[{"urls":"stun:turn.teamspeak.com:3478"},{"urls":"turns:turn.example.com:5349","username":"<username>","credential":"<credential>"}]
```

При настроенном TURN медиа может идти через этот внешний сервис, но не через шлюз WebSpeak. Без TURN используются только прямые ICE-пути и STUN.

### Кроссплатформенная P2P-трансляция экрана

Пользователи браузера и нативные клиенты TeamSpeak 6 могут обнаруживать, запускать и смотреть трансляции друг друга. Между браузерами, а также между браузером и нативным клиентом, экран передаётся по прямому соединению WebRTC/ICE, когда это возможно; WebSpeak отвечает за авторизацию сессии, состояние трансляции и передачу SDP/ICE-сигналов, но не переносит медиаданные экрана. Интерфейс показывает статус трансляции и число зрителей и предоставляет регулировку громкости, полноэкранный режим и выход. Для захвата доступны настройки до 1080p и 60 FPS, а также статистика WebRTC.

### Зависимости и источники

- WebRTC использует [werift](https://github.com/shinyoshiaki/werift-webrtc) `0.24.4`; upstream-проект распространяется по лицензии MIT.
- Протокол TeamSpeak реализован через SDK [EchoSixHIYA/teamspeak-js](https://github.com/EchoSixHIYA/teamspeak-js); собранные файлы SDK включены в репозиторий в каталоге `vendor/teamspeak-client/`.

## 🚀 Развертывание

| Способ | Подходит для |
| --- | --- |
| Docker Compose | Постоянного сервера и простых обновлений |
| Пакет Release | Запуска без Node.js и инструментов сборки |
| Из исходников | Разработки и настройки проекта |

### Docker Compose

```bash
git clone --depth 1 https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak.git
cd WebSpeak-client-for-TeamSpeak
docker compose pull
docker compose up -d
```

После запуска откройте `http://<ваш-хост>:3040/admin`, войдите с одноразовым токеном настройки из журнала первого запуска (`Admin setup token: ws-setup-…`), сразу смените пароль и настройте TeamSpeak; после смены пароля токен недействителен. Данные хранятся в volume `webspeak-data`. Не используйте `docker compose down -v`, если не хотите удалить базу и настройки.

### Пакет Release

Скачайте из [GitHub Releases](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/releases/latest) подходящий `windows-x64.zip`, `linux-x64.tar.gz` или `linux-arm64.tar.gz`, распакуйте и запустите соответствующий скрипт запуска. Пакеты уже содержат среду выполнения Node.js и производственные зависимости. Docker-образы поддерживают amd64/arm64.

### Из исходников

```bash
git clone https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak.git
cd WebSpeak-client-for-TeamSpeak
npm ci --ignore-scripts
npm rebuild @discordjs/opus --foreground-scripts
npm --prefix web ci
npm --prefix web run build
npm run build
npm start
```

## ⚠️ Требования и замечания

- Node.js `>=22.5` нужен для сборки из исходников; Docker и Release уже содержат необходимые компоненты.
- Нужен современный Chrome, Edge или другой браузер с WebRTC. Микрофон и звук окна обычно требуют HTTPS.
- WebSpeak должен иметь доступ к TeamSpeak; стандартный голосовой порт — `9987`.
- Веб-сервис использует `3040/TCP`; для публичного сайта направьте HTTPS и WebSocket через обратный прокси и задайте `WEBSPEAK_TRUST_PROXY=1`, чтобы лимиты и журналы видели реальный адрес клиента.
- Для IPv6 нужен маршрутизируемый IPv6, включённый IPv6 в ОС/контейнере и правила firewall. Литерал задаётся как `[2001:db8::1]#9987`.
- Одна сохранённая браузерная идентичность может использоваться только одним активным подключением.
- Фоновая музыка доступна только на компьютере и требует WebRTC.
