# WebSpeak 0.2.6

本版本以 [0.2.5 正式版](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/releases/tag/v0.2.5) 为基线。除了用户可见功能和问题修复，0.2.6 还完成了覆盖 TeamSpeak 网关、共享协议、语音工作区与管理页面的大范围工程结构重构。

## 工程结构重构

- **服务端语音网关：** 将原本集中在语音桥接中的工作拆分为 TeamSpeak 命令、会话事件、会话音频、语音协议和屏幕共享协调模块；客户端命令、服务端消息、音频与屏幕共享协议抽取为共享契约。
- **前端语音与管理：** 将大型 Vue 页面拆分为语音工作区、成员、聊天、音频、身份和屏幕共享组件；把连接、聊天、成员、身份、性能及屏幕共享逻辑放入职责明确的 composables 和服务。
- **管理后台与样式：** 将管理操作、服务器设置和皮肤管理拆分为独立组件与状态模块；分离管理页和语音客户端样式，并补充移动端样式层。
- **生命周期与测试：** SDK 事件、目录同步、头像传输、音频资源、屏幕共享及异步请求绑定到所属会话或页面。重连、切页或组件卸载时，旧操作不能再覆盖当前状态。新增的单元和集成测试覆盖这些边界与竞态。

## 功能与问题修复

- **[#10](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/issues/10)：** 修复 Docker/Compose 中短主机名的 DNS 回退；云端昵称发现增加超时和直接连接回退；HTTPS 部署的健康检查按证书配置使用 HTTPS。
- **[#9](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/issues/9)：** 支持从 TeamSpeak 3 身份 INI 或身份字符串导入，转换并导出 WebSpeak/TeamSpeak 兼容身份；在本地校验格式和密钥一致性。
- **[#6](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/issues/6)：** 静音同步遭遇服务端频率限制时有限重试；切换会话或重连后，旧请求不能覆盖当前麦克风状态。
- **[#7](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/issues/7)：** TS6 屏幕共享清理等待服务器确认、携带清理原因，并对频率限制有限重试，避免本地先显示清理成功。
- **[#12](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/issues/12)：** 管理员可配置公网媒体地址、IPv6 候选和语音 STUN，供反向代理或 TCP 隧道后的媒体路径使用。STUN 只发现地址，不中继音频；直接媒体仍要求客户端能访问 UDP/IPv6 路径。
- **[PR #13](https://github.com/wslinnn/WebSpeak-client-for-TeamSpeak/pull/13)：** 修复新 WebSpeak 会话漏掉既有 TS6 原生屏幕共享的问题；由重构后的服务器级协调器实现发现与同步。
- **语音与 WebRTC：** 隔离重连前后的音频帧、播放回调、SDK/目录事件和性能统计；保留连续 Opus 编码状态，只协商当前网关支持的参数；切换麦克风或伴奏设置时尽可能保留正在工作的采集链路，闭麦时伴奏仍可播放。
- **移动端：** 优化窄屏布局和语音控制；语音会话期间保持屏幕常亮。

## 发布包与架构

- Windows：`windows-x64.zip`。
- Linux：`linux-x64.tar.gz`、`linux-arm64.tar.gz`。
- Docker：同一镜像标签提供 `linux/amd64` 和 `linux/arm64`。
- Android：`arm64-v8a`、`armeabi-v7a`、`x86_64` 三种 APK。APK 使用 Android debug 签名，适合手动安装和测试，不是 Google Play 发布包。
- `SHA256SUMS.txt` 提供 Release 附件的 SHA-256 校验值。

Windows ARM64 未纳入本次发布：当前 `@discordjs/opus` 原生依赖不支持该构建目标。Android 已构建并提供安装包，但 Android 真机 TeamSpeak 连接、双向语音和后台行为仍需单独验收。

## 验证

GitHub Actions 发布流程通过自动化测试、类型检查和前后端构建；Docker 镜像执行启动检查，Windows x64 与 Linux x64/ARM64 发布包执行内置健康检查，Android 流程构建三种 ABI 的 APK。自动化构建通过不代表已完成真实 TeamSpeak 服务器互通或 Android 真机媒体验收。
